# TaskFlow Mobile

A React Native (TypeScript) Android app for the same TaskFlow Supabase backend
used by the web app, Tauri desktop app, and Chrome extension in
`real time application/`. This is a fourth, independent client — no backend
code, database schema, or business logic is duplicated; it talks to the same
Supabase project directly.

This project is intentionally **separate** from the rest of `real time
application/` — its own `package.json`, dependencies, and native `android/`
project — living at `real time application/mobile-app/` alongside
`chrome-extension/` and `src-tauri/`.

> **Note:** this folder lives inside OneDrive sync (same as the rest of the
> repo), which has repeatedly caused build-cache corruption for `.next/` in
> the Next.js project and cost real time debugging that twice. Gradle, the
> Android SDK, and Metro's cache all do the same kind of rapid, large file
> writes — if you hit similarly inexplicable Android/Metro build errors,
> suspect OneDrive sync first (see the Next.js project's incident history)
> before assuming the code or config is wrong.

## Project structure

```
mobile-app/
├── App.tsx                     Entry point: auth-gated root (Login vs Tasks)
├── src/
│   ├── config.ts                Supabase URL + anon key (same project as web/desktop/extension)
│   ├── lib/supabase.ts           Supabase client (AsyncStorage-backed session persistence)
│   ├── types/{task,database}.ts  Mirrors the Next.js project's types — same `tasks` table shape
│   ├── hooks/
│   │   ├── useAuth.tsx            Session state via onAuthStateChange, seeded from AsyncStorage
│   │   └── useTasks.ts            Fetch/create/edit/delete + Realtime subscription
│   ├── screens/
│   │   ├── LoginScreen.tsx
│   │   └── TasksScreen.tsx        List + FAB to create, tap to edit, swipe-delete, logout
│   └── components/
│       ├── TaskItem.tsx
│       └── TaskFormModal.tsx      Shared create/edit form (bottom sheet)
└── android/                      Native Android project (generated by React Native CLI)
```

## How it connects to Supabase

Same project, same Auth users, same `tasks` table and Row Level Security
policies as everywhere else — see `supabase/schema.sql` in the Next.js
project. `src/config.ts` holds the same public URL/anon key already shipped
in the web app's browser bundle and the Chrome extension's `config.js`;
nothing secret is duplicated, and RLS enforces per-user access exactly as
it does for every other client.

## Running it

```bash
cd "real time application/mobile-app"
npx react-native run-android
```

Requires an Android emulator already running (`emulator -avd <name>`) or a
device connected — see the setup instructions provided alongside this
project for installing the Android SDK, creating an AVD, and launching the
emulator.
